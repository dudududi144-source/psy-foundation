# MUSICAL CONSUMER CONTRACT

How PSY4 (or any PSY device) will eventually consume the foundation's musical
substrate. No UI dependency. No AudioContext dependency. No Radio dependency.
No Transport ownership.

## What the consumer receives

### MusicalContext
The canonical representation of the musical situation. The consumer reads it;
it does not own it.

```typescript
import type { MusicalContext } from '@psy-foundation/music';

// The consumer reads context to decide what to play:
const ctx: MusicalContext = contextSource.get();
// ctx.tonic, ctx.scaleName, ctx.energy, ctx.tension, ctx.sectionRole...
```

### MotifMemory
The store of musical material. The consumer queries it; it does not manage it.

```typescript
import { MotifMemory } from '@psy-foundation/music';

const memory = new MotifMemory();
const candidates = memory.findByRole('lead', 5);
const similar = memory.findSimilar(targetMotif, 3);
```

### PhrasePlan
An 8-bar plan generated by the foundation. The consumer executes it.

```typescript
import { planPhrase } from '@psy-foundation/music';

const plan = planPhrase({ bars: 8, seed: 42, context: ctx, memory });
// plan.slots[0] = { barIndex: 0, role: 'STATEMENT', motifId: '...', density: 0.7, energy: 0.8 }
```

### SectionPlan
A 32-64 bar plan with density/energy/novelty curves.

```typescript
import { planSection } from '@psy-foundation/music';

const section = planSection({ bars: 64, seed: 42, context: ctx });
// section.slots[0] = { barIndex: 0, sectionRole: 'ESTABLISH', density: 0.5, energy: 0.6, novelty: 0.3 }
```

### CandidateScore
Explainable scoring for motif candidates.

```typescript
import { CandidateScorer } from '@psy-foundation/music';

const scorer = new CandidateScorer({ memory, learnedWeights });
const best = scorer.pickBest(candidates, ctx, plan.slots[0], previousMotif);
// best.scores.harmonic = 0.91, best.scores.novelty = 0.67, best.final = 0.79
// best.explanation = "harmonic=0.91 rhythm=0.72 novelty=0.67..."
```

### MusicalityHealthReport
Detects "flat loop" before it reaches the user.

```typescript
import { measureMusicality, healthReport } from '@psy-foundation/music';

const metrics = measureMusicality(notesPlayed, { bars: 64, stepsPerBar: 16 });
const report = healthReport(metrics);
if (!report.healthy) {
  console.warn('Musicality issues:', report.issues);
  // ['pitchClassDiversity too low (0.17 < 0.30)', 'exactRepeatRatio too high (0.92 > 0.50)']
}
```

### MusicalLearning
Real weighted-preference learning. The consumer reports outcomes; the learning
system updates weights that influence future candidate scoring.

```typescript
import { MusicalLearning, defaultMusicalReward } from '@psy-foundation/learning';

const learning = new MusicalLearning({ learningRate: 0.1 });

// After a motif is played:
learning.observe({
  motif: playedMotif,
  outcome: 'sounded',
  reward: defaultMusicalReward('sounded'),
  bar: currentBar,
});

// The learned weights feed back into CandidateScorer:
const weights = learning.getWeights();
const scorer = new CandidateScorer({ memory, learnedWeights: weights });
```

## What the consumer does NOT do

- Does NOT manage musical time (Transport owns that)
- Does NOT manage its own BPM/beat/bar (reads from Transport snapshot)
- Does NOT manage radio analysis (Radio layer owns that)
- Does NOT hardcode patterns (uses PhrasePlan/SectionPlan)
- Does NOT manage motif storage (MotifMemory owns that)
- Does NOT score candidates (CandidateScorer owns that)
- Does NOT measure diversity (diversity.ts owns that)

## Data flow (consumer perspective)

```
1. Transport.snapshot() → read bpm, beat, bar
2. Radio observation → MusicalContext update
3. planSection() → 64-bar SectionPlan
4. planPhrase() → 8-bar PhrasePlan (per section chunk)
5. MotifMemory.findSimilar/findByRole → candidate motifs
6. Transformations → generate more candidates
7. CandidateScorer.pickBest → best motif for this bar
8. Consumer plays the motif (AudioContext scheduling)
9. Report outcome → MusicalLearning.observe()
10. measureMusicality() → MusicalityHealthReport → adjust if unhealthy
```

## Radio adaptation flow (P5.5)

The radio is EVIDENCE, not AUTHORITY. The foundation's own composition
identity (style grammar, motif memory, arrangement plan) always wins.
Radio context only ADAPTS the foundation's intent — it never overrides it.

```
CompositionPlan + RadioMusicalContext
        │
        ▼
CompositionAdaptation.adapt(...)
        │
        ▼
AdaptedCompositionIntent
   { groovePressure, bassPressure, leadPressure,
     counterPressure, texturePressure,
     densityTarget, tensionTarget, noveltyTarget,
     registerShift, restPressure,
     motifPreference, harmonyPreference, confidence, reasons }
        │
        ▼
applyAdaptation(baseBars, intent)
        │
        ▼
MusicalEvent[]
```

### RadioMusicalContext

The radio analyser's output. Carries tempo / key / energy / role-occupancy /
groove-fingerprint / style / position estimates, each with its own
confidence. When the analyser is unavailable, pass `RADIO_ABSENT`.

```typescript
import { createRadioContext, RADIO_ABSENT } from '@psy-foundation/music';

const radio = createRadioContext({
  bpm: 145, bpmConfidence: 0.8,
  key: 4, scale: 'phrygian-dominant', keyConfidence: 0.75,
  energy: 0.7, density: 0.6, energyConfidence: 0.7,
  kickOccupancy: 0.5, bassOccupancy: 0.85, percussionOccupancy: 0.4,
  leadOccupancy: 0.45, harmonicOccupancy: 0.3,
  syncopation: 0.3, style: 'full-on', styleConfidence: 0.75,
  sectionLikelihood: 'GROOVE',
  confidence: 0.8, available: true,
});
```

### OpportunityMap

Classifies each role as OCCUPIED / OPEN / MEDIUM based on radio occupancy.

```typescript
import { buildOpportunityMap } from '@psy-foundation/music';

const opportunities = buildOpportunityMap(radio);
// { kick: 'MEDIUM', bass: 'OCCUPIED', lead: 'MEDIUM',
//   harmony: 'OPEN', counter: 'OPEN', texture: 'MEDIUM',
//   transition: 'OPEN' }
```

### AdaptedCompositionIntent

The adaptation layer's verdict: which roles to emphasise, what
density / tension / novelty to target, which motif transform to prefer,
how strongly to rest. NEUTRAL when the radio is absent or low-confidence.

```typescript
import { CompositionAdaptation } from '@psy-foundation/music';

const adaptation = new CompositionAdaptation();
const intent = adaptation.adapt({
  baseContext, radio, opportunities,
  currentBar: 32, phraseBar: 4,
});
// intent.bassPressure = 0.2 (radio bass OCCUPIED → don't compete)
// intent.counterPressure = 0.85 (lead space → counter-response)
// intent.restPressure = 0.1
// intent.motifPreference = 'REUSE'
// intent.reasons = ['radio bass OCCUPIED — reducing bass pressure', ...]

// Apply the intent to composed bars:
const adaptedBars = applyAdaptation(baseSection.bars, intent);
```

### Confidence handling

- `radio.confidence < 0.3` → NEUTRAL intent (preserve base composition)
- `radio.confidence 0.3-0.7` → partial adaptation (blend 50%)
- `radio.confidence > 0.7` → strong adaptation

### Mid-phrase stability

- `phraseBar < 4` → defer adaptation to next phrase boundary (NEUTRAL)
- `phraseBar >= 4` → adapt at next bar boundary

### Learning

The adaptation layer keeps a per-role learned bias. Call `reinforce(role,
success)` after observing whether a role's adaptation worked well. A
negative outcome reduces that role's pressure on the next call.

```typescript
// After a bar where the foundation's bass clashed with the radio's bass:
adaptation.reinforce('bass', false);
// Next adapt() call will have a lower bassPressure.
```

### Identity preservation

When the same song (seed + style) is adapted under different radios:
- **Form divergence < 0.3** (arrangement states / phrase structure preserved)
- **Role divergence > 0.3** (roles emphasised differently per radio)

The foundation's identity wins. The radio only shapes which parts the
foundation emphasises.

## Migration path (NOT in this gate)

Phase E (post-P3):
1. PSY4 imports foundation MusicalContext types
2. PSY4's psyLive reads MusicalContext instead of hardcoded presets
3. PSY4's patternMutator is replaced by foundation transformations
4. PSY4's learning.ts is replaced by MusicalLearning
5. PSY4's hardcoded patterns are replaced by MotifMemory + PhrasePlan

Phase F:
6. PSY4 deletes its musical subsystems
7. PSY4 consumes foundation exclusively
